# 恒源云部署指南（Muv-luv-translation）

> 面向要在恒源云 GPU 实例上部署本项目的操作者。视频日语字幕 → 简体中文翻译工具。
> 处理流程见仓库 `README.md`「核心流程」，本文只讲「连接恒源云 + 部署项目 + 数据进出」。

## 1. 实例选择建议

- 显卡：**必须带 NVIDIA NVENC**（N 卡基本都支持）。本管线 GPU 需求是硬件编码 + 轻量 OCR 推理，**不需要顶级卡**（4060 Ti / 3070 / 3090 均可，显存 ≥8GB 即可）。
- CPU：**核数 ≥8（越多越好）**，用于并行渲染与 OCR 多进程（渲染是最耗时环节且吃 CPU）。
- 内存：≥16GB。
- 镜像：选带 NVIDIA 驱动的 PyTorch 官方镜像（自带 ffmpeg/驱动，最省事），Python ≥3.11。

## 2. 创建并启动实例

恒源云控制台 → 我的实例 → 创建实例 → 选配置/镜像 → 开机。
实例启动后，**记录控制台显示的 SSH 信息**（主机名、端口、密码）。

## 3. SSH 连接

```bash
ssh -p <端口> root@<主机名>     # 例如 ssh -p 47644 root@i-2.gpushare.com
```
输入控制台给的密码。之后建议上传本机公钥免密登录（`ssh-copy-id`）。

## 4. 一键初始化项目

实例上执行（脚本来自本仓库 `scripts/init_instance.sh`）：

```bash
curl -sL https://raw.githubusercontent.com/shiny-p/Muv-luv-translation/main/scripts/init_instance.sh -o init_instance.sh
bash init_instance.sh '<DASHSCOPE_API_KEY>' '<DEEPSEEK_API_KEY>'
```

- 两个 key 均可选；不传则稍后手动填 `/root/Muv-luv-translation/.env`。
- 脚本会自动：装依赖（ffmpeg/中文字体）→ 校验 NVENC → clone 仓库 → 建 venv 装依赖 + onnxruntime-gpu → 写 GPU 配置（CUDA OCR / NVENC / 1920 / 固定台词区 / 中文字体）→ 写 `.env` → 验证。
- **翻译供应商**：默认千问 DashScope（`deepseek-v4-flash-0731`），key 读 `DASHSCOPE_API_KEY`；DeepSeek 的 key 可同时留在 `.env`（`DEEPSEEK_API_KEY`），改 `config.yaml` 的 `translation.provider/base_url/api_key_env/model` 即可切换。

## 5. 把视频弄进实例

实例项目约定：源视频放 `/hy-tmp/`（关机后保留约 24h，重启前及时取走成品）。

**方式 A：恒源云 OSS（个人数据）中转**（推荐，简单）
```bash
# 本地（恒源云 oss 工具）：上传 zip（OSS 只收压缩包）
oss login   # 账号=恒源云账号
oss cp /本地/视频.zip oss://

# 实例上：下载并解压
oss login
oss cp oss://视频.zip /hy-tmp/
cd /hy-tmp && unzip 视频.zip
```

**方式 B：百度网盘**（需先在恒源云控制台授权百度/阿里云盘账号，见官方「公共网盘」文档）
```bash
# 实例上安装 gpushare-cli 并登录（账号=恒源云控制台账号密码）
curl -L https://download.gpushare.com/download/gpushare-cli-linux -o /usr/local/bin/gpushare-cli && chmod u+x /usr/local/bin/gpushare-cli
gpushare-cli login -u <恒源云账号> -p <密码>
gpushare-cli baidu down /网盘路径/视频.zip /hy-tmp/
```

## 6. 处理视频

严格按 README「核心流程」**分步**执行（禁止 `all`，除非明确命令）：
```bash
cd /root/Muv-luv-translation
V=/hy-tmp/<视频>_output/<视频>_cfr.mp4   # 由第 1 步生成
.venv/bin/python run.py cfr /hy-tmp/<视频>.mp4
.venv/bin/python run.py ocr  $V --jobs 2
.venv/bin/python run.py translate $V
.venv/bin/python run.py render $V
```
每步检查点、区域修正、翻译全量扫描等见 README。

## 7. 成品交付（上传百度网盘）

处理完成后把**整个输出文件夹**打成 zip 传百度（改 JSON 可重渲染，不用重跑流水线）：
```bash
cd /hy-tmp && zip -0 -q -r <视频>_output.zip <视频>_output/
gpushare-cli baidu up /hy-tmp/<视频>_output.zip /MuvLuv_成品/
```
> 注意：`gpushare-cli` **一次只跑一个上传**（并发会崩溃）；上传完用 `gpushare-cli baidu ls /MuvLuv_成品` 核对。

## 8. 常见问题

- **NVENC 不可用**：确认 `ffmpeg -encoders | grep h264_nvenc` 有输出；无则换带 NVIDIA 驱动 ffmpeg 的镜像。
- **音画不同步（VFR 源视频）**：管线第 0 步已自动转 CFR，无需手工处理。
- **翻译报缺 key**：检查 `.env` 里 `DASHSCOPE_API_KEY` / `DEEPSEEK_API_KEY`。
- **上传很慢**：实例出口带宽约 4.5MB/s 是平台限制，会员只加速下载端；上传仍首选百度（阿里云盘从实例上传更慢）。
- **显卡利用率低**：正常（NVENC/CPU 为主），GPU 算力对本管线溢出，但不要换成无 GPU 的纯 CPU 实例（渲染会慢数倍）。
